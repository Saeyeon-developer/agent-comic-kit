# agent-comic-kit 기획

AI 에이전트(Claude Code, Codex 등)와 대화하며 만화(comic)를 만드는 툴. 기본 출력은 SNS용 슬라이드이고, 읽기 방향·화풍·형식은 프로젝트마다 사용자가 정합니다.
1단계는 GPT Image(Codex 내장 이미지 도구)를 기준으로 개발합니다. Claude Code 같은 에이전트에서는 [codex-image-relay](https://github.com/Saeyeon-developer/codex-image-relay)로 호출합니다.

## 1. 확정된 결정

| 항목 | 결정 |
|---|---|
| 이미지 생성 | **GPT Image 기준으로 개발.** Claude Code 등은 codex-image-relay로, Codex는 내장 `image_gen`으로 직접 생성. 프롬프트 작성 규칙은 공개된 [`gpt-image-25`](https://github.com/Saeyeon-developer/AI-video-prompt-skill/tree/main/gpt-image-25) 스킬을 함께 설치해 참고 |
| 생성 단위 | **혼합.** 기본은 1~3컷을 한 장(페이지 = SNS 슬라이드 한 장)으로 생성하고, 문제 있는 컷만 따로 재생성해 교체 |
| 대사 식자 | **둘 다 지원, 기본은 오버레이.** 그림에는 말풍선 자리만 비우고 대사는 프로그램이 그려 넣음. 이미지에 직접 그리는 방식도 선택 가능 |
| 툴 형태 | **1단계: 스킬 + Python CLI**, 결과는 HTML 미리보기로 확인 |
| 데이터 형식 | **YAML** (PyYAML 사용) |
| 출력 규격 | **SNS(인스타그램, X) 프리셋을 예시로 제공.** 고정값이 아니라 인터뷰에서 고른 값을 쓰고, 사용자가 프리셋 파일을 고치거나 추가해 자기 플랫폼에 맞출 수 있게 함 (→ 3장) |
| 캐릭터 시트 | **툴이 시트 제작을 도움.** 설명이나 사용자 그림으로부터 시트를 만들고, 다듬고, 승인하는 단계를 별도로 둠 (→ 6장) |
| 연출 권한 | **사용자 지시가 우선.** 사용자가 구도·장면을 구체적으로 정하면 그대로 따르고, 줄거리와 대사만 주면 에이전트가 연출을 맡음 (→ 7장) |
| 이름과 용어 | **저장소 `agent-comic-kit`, 상위어는 comic.** webtoon·manga는 특정 형식을 떠올리게 하므로 이름과 프롬프트의 화풍 지시에 쓰지 않음. README·토픽에는 검색용으로 manga, webtoon, manhwa를 함께 표기 |
| 형식·화풍 결정 | **고정값 없음, 프로젝트 시작 인터뷰로 정함.** 프리셋은 예시일 뿐이며, 읽기 방향·화풍·출력 형식을 사용자에게 묻고 작품 설정에 기록 (→ 3장, 4장) |

## 2. 전체 구조

```
agent-comic-kit/
├─ SKILL.md              에이전트용 제작 흐름 (단계별 확인 지점 포함)
├─ presets/formats/      출력 규격 프리셋 (사용자가 복사·수정해서 추가)
├─ comic/                Python CLI (명령: comic ...)
│   ├─ init              작품 폴더 생성
│   ├─ cast              캐릭터 시트 생성·승인·관리
│   ├─ prompt            콘티 → 이미지 프롬프트 조립 (화풍·캐릭터 설명은 매번 똑같이 붙임)
│   ├─ gen               프롬프트 + 레퍼런스 → 이미지 생성
│   ├─ split / swap      페이지 → 컷 분리, 재생성한 컷 교체
│   ├─ letter            말풍선·대사 오버레이
│   ├─ export            프리셋 규격으로 최종 이미지 출력 (슬라이드 묶음 또는 세로 스트립)
│   └─ preview           HTML 미리보기 (실제 SNS 화면과 비슷하게)
└─ backends/
    ├─ codex-relay       imagen.ps1 호출 (Claude Code 등)
    └─ agent             프롬프트·레퍼런스 목록만 내보내고, 에이전트가 자기 이미지 도구로 만든 파일을 가져옴
                         (Codex 내장 image_gen 등)
```

## 3. 출력 규격 프리셋

규격은 코드에 박아 두지 않고 `presets/formats/*.yaml` 파일로 둡니다. 작품의 `comic.yaml`에서 프리셋 이름을 고르고, 필요하면 값을 덮어씁니다. 다른 플랫폼에 맞추려면 프리셋 파일 하나를 복사해 수정하면 됩니다.

```yaml
# presets/formats/instagram-carousel.yaml (예시)
name: instagram-carousel
kind: slides            # slides(장 단위) | scroll(세로 스크롤)
width: 1080
height: 1350            # 4:5
max_slides: 20
same_ratio_required: true
file: { type: jpg, quality: 92, max_mb: 8 }
safe_margin: 0.05       # 가장자리 5%에는 대사·중요 요소를 두지 않음
checked: 2026-10        # 규격 확인 시점. 플랫폼 정책이 바뀌면 갱신
```

예시로 제공할 프리셋 (2026년 10월 확인 값, 출시 전에 다시 확인). **프리셋은 출발점일 뿐이며, 어떤 프리셋도 "웹툰이란 이런 것" 같은 정의가 아닙니다.** 인터뷰에서 사용자가 고른 값이 항상 우선합니다.

| 프리셋 | 형태 | 크기 | 비고 |
|---|---|---|---|
| `instagram-carousel` (기본값) | 슬라이드 | 1080×1350 (4:5) | 최대 20장, 모든 장이 같은 비율이어야 함 |
| `instagram-carousel-34` | 슬라이드 | 1080×1440 (3:4) | 2026년 추가된 비율. 생성 비율(2:3)과 가까워 잘려 나가는 부분이 적음 |
| `x-post` | 슬라이드 | 1080×1350 (4:5) | 게시물당 최대 4장, 그 이상은 스레드로 나눔. 타임라인 미리보기는 잘려 보임 |
| `vertical-scroll` | 세로 스크롤 | 폭 800, 일정 높이마다 분할 | 세로 스크롤 형식이 필요한 플랫폼·블로그용 |

**생성 비율 = 출력 비율 (실험 03에서 확인):** 이미지 도구는 프롬프트에 적은 비율을 정확히 따릅니다(4:5 → 1122×1402, 2.4:1 → 1942×809). 픽셀 수는 약 1.57MP로 일정합니다. 그래서 페이지는 처음부터 프리셋 비율로, 다시 그리는 컷은 해당 슬롯 비율로 요청합니다. 생성 후 잘라내는 안전 영역 방식은 쓰지 않습니다. 4:5 페이지(1122×1402)는 1080×1350보다 커서 확대도 필요 없습니다.

## 4. 프로젝트 시작 인터뷰

형식과 화풍을 툴이 미리 정하지 않습니다. 새 작품을 시작할 때 에이전트가 아래 항목을 사용자에게 묻고, 답을 `comic.yaml`에 기록합니다. 사용자가 이미 말한 항목은 다시 묻지 않고, 모르겠다고 하면 예시와 함께 추천안을 제시합니다.

| 항목 | 질문 예시 | 기록 위치 |
|---|---|---|
| 올릴 곳·출력 형식 | 어디에 올리나요? 장 단위(슬라이드)인가요, 세로 스크롤인가요? 크기는? | `format` (프리셋 이름 + 덮어쓸 값) |
| 읽기 방향 | 컷과 말풍선을 왼쪽→오른쪽, 오른쪽→왼쪽, 위→아래 중 어떤 순서로 읽나요? | `reading_direction` |
| 화풍 | 어떤 그림체인가요? 참고 이미지가 있나요? | `style.description` (눈에 보이는 특징으로 풀어 쓴 문구), `style.refs` |
| 색 | 풀컬러, 흑백, 흑백+톤, 한두 가지 강조색 등 | `style.color` |
| 언어와 폰트 | 대사 언어, 원하는 글꼴 느낌 | `lettering.language`, `lettering.font` |
| 분량 | 한 화(게시물)당 장 수, 장당 컷 수 | `episode_defaults` |
| 연출 관여도 | 구도를 직접 정하고 싶은지, 에이전트에게 맡길지 | `direction.mode` |

화풍 문구는 "manga", "webtoon" 같은 장르 이름 대신 눈에 보이는 특징으로 적습니다. 예: "일본 애니메이션 팬아트 풍 풀컬러, 깔끔한 선화, 셀 채색". 장르 이름은 이미지 모델이 특정 형식(흑백·스크린톤, 세로 구도 등)으로 기우는 원인이 되기 때문입니다.

## 5. 작품 폴더 구조 (초안)

```
my-comic/
├─ comic.yaml                 제목, 화풍 설명, 출력 프리셋(+덮어쓸 값), 언어, 폰트
├─ cast/
│   └─ yuna/
│       ├─ character.yaml    외형 설명(고정 문구), 의상 버전, 말투, 승인 상태
│       ├─ drafts/           시트 후보들
│       └─ refs/             승인된 시트, 얼굴 클로즈업
├─ locations/                (선택) 배경 레퍼런스
└─ episodes/ep01/
    ├─ script.yaml           콘티: 페이지(=슬라이드) → 컷(구도, 등장인물, 행동, 대사, 말풍선 위치, 효과음)
    ├─ pages/                p01.png, p01.v2.png … (+ 생성 기록 .json)
    ├─ panels/               분리된 컷, 교체된 컷
    ├─ lettered/             식자 완료 페이지
    └─ out/                  프리셋 규격으로 출력된 최종 이미지, preview.html
```

## 6. 캐릭터 시트 제작

캐릭터 일관성의 기준이 되는 단계이므로 별도 단계로 둡니다.

1. **입력:** 텍스트 설명, 사용자가 그린 그림이나 사진, 기존 캐릭터 이미지 중 무엇이든.
2. **외형 고정 문구 작성:** 에이전트가 머리 모양·색, 눈, 체형, 의상, 소품을 짧고 구체적인 문구로 정리해 `character.yaml`에 저장합니다. 이후 모든 프롬프트에 이 문구를 그대로 붙입니다.
3. **시트 생성:** 한 장에 전신 정면·측면·뒷모습과 표정 4종을 담습니다(가로 이미지). 후보는 `drafts/`에 저장합니다.
4. **다듬기:** 사용자의 피드백을 받아 수정 사항을 하나씩 반영해 다시 생성합니다.
5. **승인:** 사용자가 승인하면 `refs/`로 옮기고, 얼굴 클로즈업을 잘라 둡니다. **승인된 시트가 없는 캐릭터는 페이지에 등장시키지 않습니다.**
6. **변형:** 의상 변경이나 성장 같은 버전은 같은 캐릭터 아래 별도 버전으로 관리합니다.

## 7. 연출 권한과 권장 모델

콘티의 각 항목에 "누가 정했는지"를 기록합니다.

- **사용자가 정한 항목**(구도, 앵글, 표정, 배치 등)은 `by: user`로 표시하고, 에이전트가 바꾸지 않습니다. 개선 의견이 있으면 제안만 합니다.
- **정해지지 않은 항목**은 에이전트가 연출합니다: 컷 나누기, 샷 크기, 앵글, 시선 흐름, 말풍선 위치, 페이지(슬라이드)당 컷 수, 장면 전환.
- **같은 사용자도 경우에 따라 다릅니다.** 어떤 컷은 구체적으로 지시하고 나머지는 맡기는 식으로 섞여도 됩니다.

SKILL.md에 다음 권장 문구를 넣습니다. 핵심은 특정 모델명이 아니라 **비전 능력과 연출 능력을 갖춘 상위 모델**을 쓰는 것입니다. 예시 모델명은 시간이 지나면 바뀌므로 예시로만 둡니다.

> 연출(콘티 작성, 컷 구성, 프롬프트 작성)과 결과 검수(생성된 이미지를 보고 캐릭터 일관성·연출 의도를 판단)를 에이전트에게 맡길 때는, 이미지를 정확히 읽는 비전 능력과 만화 연출 지식을 갖춘 상위 모델을 권장합니다. 예: gpt-6-astra, Claude Opus 5.5, Claude Fable 계열 최신 모델. 이미지 생성 호출 자체는 가벼운 모델로 충분합니다(codex-image-relay의 `Final` 모드).

## 8. 실험 결과와 확정된 파이프라인

실험 기록과 실험 자료(캐릭터 이미지 등)는 저장소에 포함하지 않습니다.

| 실험 | 결과 | 설계 반영 |
|---|---|---|
| 01 캐릭터 시트 | 3D 스크린샷 4장 → 2D 시트, 두 캐릭터 모두 1회 만에 성공 | 사용자 이미지 → 시트 흐름 그대로 채택 |
| 02 페이지 → 분리 → 교체 | 2인 2컷 페이지 생성, XY-cut 분리 정확, 컷 단독 재생성 시 원래 페이지를 레퍼런스로 주면 화풍 일치 | 혼합 생성 방식 확정. 키 차이는 프롬프트 한 줄로 충분 |
| 02 여백 | 여백 비율 지시는 부정확(8% 요청 → 4~5%) | 생성된 페이지를 그대로 쓰지 않고 **분리한 컷을 출력 캔버스에 다시 배치(compose)** |
| 03 비율 | 비율은 프롬프트로 정확히 지정됨 | 페이지·컷을 출력 비율로 직접 생성 |
| 04 식자 | 말풍선 4종·한글 줄바꿈 정상. 위치는 "배치 → 확인 → 수정" 1회로 해결 | 식자 위치는 에이전트가 이미지를 보고 확정하는 단계로 둠 |

확정된 파이프라인 (한 페이지 기준):

```
콘티(script.yaml)
 → prompt page   : 프리셋 비율·레이아웃·캐릭터 고정 문구·레퍼런스 역할을 자동 조립 (에이전트가 다듬을 수 있음)
 → gen page      : 페이지 생성
 → split         : 컷 분리 (컷 수가 콘티와 다르면 오류)
 → [검수]         : 에이전트가 컷마다 콘티와 비교 → 문제 컷만 prompt panel + gen panel (슬롯 비율로 생성) → use
 → compose       : 출력 캔버스에 규격 여백·간격·테두리로 재배치
 → letter        : 대사 배치 (컷 기준 상대 좌표) → [검수] → 좌표 수정
 → export        : 프리셋 형식으로 최종 출력 + preview.html
```

## 10. 말풍선 스타일 (확정)

| 종류 | 모양 | 용도 |
|---|---|---|
| `speech` | 둥근 타원 + 꼬리 | 일반 대사 |
| `shout` | 뾰족한 가시 테두리 | 외침, 놀람 |
| `thought` | 구름 모양 + 작은 원 꼬리 | 속마음 |
| `narration` | 사각형 상자, 꼬리 없음 | 내레이션, 시간·장소 설명 |

폰트는 함께 배포할 수 있는 OFL 라이선스 한글 폰트로 시작하고, 작품 설정에서 바꿀 수 있게 합니다.
